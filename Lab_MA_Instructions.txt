OVERVIEW
--------
In this lab, you will build a Multi-Agent Trip Planner using LangChain and
LangGraph. You will create a system where a Supervisor agent orchestrates
three specialist agents — Research, Budget, and Itinerary — to collaboratively
plan a trip that no single agent could handle alone.

By the end of this lab, you will understand:
  - What intelligent agents are and how they work in a multi-agent system
  - How to define tools and bind them to agents using LangGraph
  - How the Supervisor (orchestrator/subagent) pattern coordinates agents
  - Why multi-agent systems can outperform single-agent designs


PREREQUISITES
-------------
  - Python 3.10+
  - An OpenAI API key configured in .streamlit/secrets.toml
  - The following packages installed:
      pip install streamlit langchain langchain-openai langgraph langgraph-supervisor

================================================================================
  PART 2: BUILDING SPECIALIST AGENTS (~10 minutes)
================================================================================

Goal: Understand how tools and agents are defined in LangGraph.

Steps:
  1. Read through the THREE tool functions defined with the @tool decorator:

     a) search_destination(query)
        - Looks up travel info (attractions, culture, weather, tips)
        - Returns simulated data for known cities (Paris, Tokyo, NYC, Rome)
        - Falls back to generic info for unknown destinations

     b) calculate_budget(destination, days, budget_level)
        - Estimates trip costs based on budget level (budget/moderate/luxury)
        - Breaks down daily costs by category
        - Includes flight estimates and money-saving tips

     c) create_schedule(destination, days, interests)
        - Builds a day-by-day itinerary based on traveler interests
        - Matches activities to interest categories (food, history, art, etc.)

  2. Note how each tool uses the @tool decorator from langchain_core.tools.
     This is what makes the function callable by an agent — it registers
     the function name, description, and parameter schema automatically.

  3. Read the THREE agent definitions using create_react_agent():

     a) research_agent — uses search_destination, named "research_agent"
     b) budget_agent — uses calculate_budget, named "budget_agent"
     c) itinerary_agent — uses create_schedule, named "itinerary_agent"

  4. Each agent gets:
     - A model (the LLM it reasons with)
     - A list of tools (what it can do)
     - A name (how the supervisor identifies it)
     - A prompt (its personality and instructions)

  ** Take a screenshot of the agent creation code for your write-up. **


================================================================================
  PART 3: CREATING THE SUPERVISOR (~8 minutes)
================================================================================

Goal: Understand how the Supervisor orchestrates the specialist agents.

Steps:
  1. Read the create_supervisor() call. Note three key arguments:
     - agents: the list of specialist agents [research, budget, itinerary]
     - model: the LLM the supervisor uses for routing decisions
     - prompt: instructions telling the supervisor HOW to route tasks

  2. Study the supervisor prompt carefully. It tells the supervisor:
     - Which agents are available and what they do
     - How to route different types of questions
     - To delegate to ALL THREE agents for full trip planning
     - To synthesize outputs into a single organized response

  3. Note the workflow.compile() call — this converts the supervisor
     workflow into a runnable LangGraph application.

  4. Key concept: The Supervisor pattern is an ORCHESTRATOR/SUBAGENT
     coordination protocol. The supervisor is the "brain" that decides
     which agents to call and in what order. The agents are the "hands"
     that do the specialized work.

     "Agent Activity Log" section. This shows:
