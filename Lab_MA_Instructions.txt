OVERVIEW
--------
In this lab, you will build a Multi-Agent Trip Planner as a Streamlit app.
A Supervisor agent will orchestrate three specialist agents — Research,
Budget, and Itinerary — to collaboratively plan a trip. No single agent
can produce a complete plan; they must coordinate through the Supervisor.

By the end of this lab you will:
  - Define custom tools using LangChain's @tool decorator
  - Create specialist agents with create_react_agent()
  - Wire them together under a Supervisor using create_supervisor()
  - Build a Streamlit UI to interact with the multi-agent system
  - Compare multi-agent output against a single-agent baseline

Time: ~40 minutes


SETUP
-----
1. Install the required packages (run in your terminal):

     pip install streamlit langchain langchain-openai langgraph langgraph-supervisor

2. Make sure your OpenAI API key is configured in .streamlit/secrets.toml:

     OPENAI_API_KEY = "sk-..."

3. You are provided a file called travel_data.json which contains all the
   destination information, cost data, and activity pools. Place this file
   in your LABS-IST488 directory.

4. Create a new file called Lab_MA.py in your LABS-IST488 directory.

5. Add Lab_MA.py to your streamlit_app.py navigation so you can access it.

================================================================================
  PART 2: BUILDING SPECIALIST AGENTS (~10 minutes)
================================================================================

In this section you will define three tools and three agents.

--- STEP 2A: Load the Travel Data ---

First, load the travel_data.json file at the top of your tools section.
This file contains all destinations, costs, activities, and tips:

    with open("travel_data.json", "r") as f:
        TRAVEL_DATA = json.load(f)

The JSON file has this structure:
  - destinations: dict of city names -> {highlights, best_time, culture, tips, weather}
  - flight_estimates: dict of city names -> estimated roundtrip flight cost (USD)
  - daily_costs: dict of budget levels -> {accommodation, food, transport, activities, misc}
  - activities: dict of interest categories -> list of activity strings
  - money_saving_tips: list of tip strings


--- STEP 2B: Define the Tools ---

Each tool is a Python function decorated with @tool. The decorator
automatically registers the function's name, docstring, and parameter
types so that an LLM agent can call it. Here is the pattern:

    @tool
    def my_tool_name(param1: str, param2: int) -> str:
        """Description of what this tool does. The LLM reads this."""
        # ... your logic ...
        return json.dumps(result)

Create THREE tools that pull data from TRAVEL_DATA:

  1. search_destination(query: str) -> str
     Purpose: Look up travel info about a destination.
     Implementation: Read TRAVEL_DATA["destinations"]. Match the user's
     query against city names (case-insensitive). Return the matching
     city's data as a JSON string. If no city matches, return generic
     fallback info.

  2. calculate_budget(destination: str, days: int, budget_level: str) -> str
     Purpose: Estimate trip costs.
     Implementation: Read TRAVEL_DATA["daily_costs"] and
     TRAVEL_DATA["flight_estimates"]. Look up the daily rate for the
     given budget level, calculate totals based on the number of days,
     add the flight cost. Include TRAVEL_DATA["money_saving_tips"].
     Return everything as JSON.

  3. create_schedule(destination: str, days: int, interests: str) -> str
     Purpose: Build a day-by-day itinerary.
     Implementation: Read TRAVEL_DATA["activities"]. Parse the interests
     string, collect matching activities from the pool, and build a
     schedule with morning/afternoon/evening slots for each day.
     Return as JSON.

TIP: These tools return SIMULATED data from the JSON file — you are not
calling real APIs. This keeps the lab self-contained and predictable.
The LLM still reasons about the data and composes a natural-language response.


--- STEP 2C: Create the Agents ---

Use create_react_agent() to create three specialist agents. Each agent
needs four arguments:

    agent = create_react_agent(
        model=agent_llm,
        tools=[your_tool],
        name="agent_name",
        prompt="You are a specialist in ... Always use the tool ..."
    )

Create these three agents:

  1. research_agent
     - Tools: [search_destination]
     - Prompt: Tell it to be a travel research specialist that always
       uses the search_destination tool to find destination info.

  2. budget_agent
     - Tools: [calculate_budget]
     - Prompt: Tell it to be a budget specialist that always uses the
       calculate_budget tool to estimate costs.

  3. itinerary_agent
     - Tools: [create_schedule]
     - Prompt: Tell it to be an itinerary specialist that always uses
       the create_schedule tool to build day-by-day plans.

IMPORTANT: In each agent's prompt, instruct it to ALWAYS call its tool
and not make up information. This ensures the agent uses the tool rather
than relying on its own knowledge.


================================================================================
  PART 3: CREATING THE SUPERVISOR (~8 minutes)
================================================================================

The Supervisor is the central orchestrator. It receives the user's request,
decides which agent(s) to delegate to, and synthesizes the final response.

Use create_supervisor() to wire the agents together:

    workflow = create_supervisor(
        agents=[research_agent, budget_agent, itinerary_agent],
        model=supervisor_llm,
        prompt="..."
    )

Write a supervisor prompt that:
  - Lists the three available agents and what each one does
  - Instructs the supervisor to route questions:
      * Destination questions -> research_agent
      * Cost/budget questions -> budget_agent
      * Schedule/itinerary questions -> itinerary_agent
      * Full trip planning -> ALL three agents
  - Tells the supervisor to synthesize all responses into one organized plan

Then compile the workflow:

    multi_agent_app = workflow.compile()

This creates a runnable multi-agent system that you can invoke with:

    result = multi_agent_app.invoke({
        "messages": [{"role": "user", "content": "your query here"}]
    })

The final response is in: result["messages"][-1].content

================================================================================
  PART 6: CHATBOT MODE — MessagesState & StateGraph (~10 minutes bonus)
================================================================================

In Parts 1-5 you used create_supervisor(), which is a HIGH-LEVEL helper
that builds a graph for you automatically. In this section you will build
a CONVERSATIONAL chatbot using the LOWER-LEVEL LangGraph primitives.
This teaches you what is happening under the hood.

KEY CONCEPTS:

  MessagesState
  -------------
  A TypedDict provided by LangGraph that holds a list of messages as the
  graph's shared state. Every node in the graph reads from and writes to
  this state. Think of it as the "conversation memory" that flows through
  the entire graph.

      from langgraph.graph import MessagesState
      # MessagesState is equivalent to:
      # class MessagesState(TypedDict):
      #     messages: list[BaseMessage]

  StateGraph
  ----------
  The core graph builder class. You use it to:
    1. Define NODES (functions that process state)
    2. Define EDGES (connections between nodes)
    3. Compile into a runnable app

      from langgraph.graph import StateGraph, START, END

  Nodes
  -----
  Each node is a Python function that:
    - Takes the current state (MessagesState) as input
    - Returns a dict with the updated messages

      def my_node(state: MessagesState):
          messages = state["messages"]    # read current messages
          # ... do something ...
          return {"messages": [response]} # add new message(s)

  Edges
  -----
  Connect nodes together. There are three types:
    - Static:      graph.add_edge("node_a", "node_b")
    - Conditional: graph.add_conditional_edges("node_a", router_fn, mapping)
    - START/END:   graph.add_edge(START, "first_node")


--- STEP 6A: Define Graph Nodes ---

Create these node functions:

  1. supervisor_node(state: MessagesState)
     - Reads the conversation messages
     - Uses the supervisor LLM with a routing prompt to decide which
       agent to call
     - The routing prompt should tell the LLM to respond with ONLY
       one word: "research", "budget", "itinerary", "all", or "chat"
     - Returns the LLM's response as a new message

  2. research_node(state: MessagesState)
     - Invokes the research_agent (from Part 2) with the current messages
     - Returns the agent's output messages

  3. budget_node(state: MessagesState)
     - Invokes the budget_agent with the current messages
     - Returns the agent's output messages

  4. itinerary_node(state: MessagesState)
     - Invokes the itinerary_agent with the current messages
     - Returns the agent's output messages

  5. run_all_agents(state: MessagesState)
     - Sequentially invokes ALL THREE agents
     - Combines all their output messages and returns them

  6. synthesizer_node(state: MessagesState)
     - Takes the full conversation (including agent outputs)
     - Uses the LLM to produce a single, well-organized response
     - This is the "final answer" node


--- STEP 6B: Define the Router ---

Create a routing function:

    def route_from_supervisor(state: MessagesState):
        last_msg = state["messages"][-1].content.strip().lower()
        if "research" in last_msg:
            return "research"
        elif "budget" in last_msg:
            return "budget"
        elif "itinerary" in last_msg:
            return "itinerary"
        elif "all" in last_msg:
            return "all"
        else:
            return "chat"

This reads the supervisor's one-word routing decision and returns the
name of the next node to execute.


--- STEP 6C: Build the StateGraph ---

Now wire everything together:

    chatbot_graph = StateGraph(MessagesState)

    # 1. Add all nodes
    chatbot_graph.add_node("supervisor", supervisor_node)
    chatbot_graph.add_node("research", research_node)
    chatbot_graph.add_node("budget", budget_node)
    chatbot_graph.add_node("itinerary", itinerary_node)
    chatbot_graph.add_node("all_agents", run_all_agents)
    chatbot_graph.add_node("synthesizer", synthesizer_node)

    # 2. Entry edge: START -> supervisor
    chatbot_graph.add_edge(START, "supervisor")

    # 3. Conditional edges: supervisor -> specialist (based on routing)
    chatbot_graph.add_conditional_edges(
        "supervisor",
        route_from_supervisor,
        {
            "research": "research",
            "budget": "budget",
            "itinerary": "itinerary",
            "all": "all_agents",
            "chat": "synthesizer",
        },
    )

    # 4. Each specialist -> synthesizer
    chatbot_graph.add_edge("research", "synthesizer")
    chatbot_graph.add_edge("budget", "synthesizer")
    chatbot_graph.add_edge("itinerary", "synthesizer")
    chatbot_graph.add_edge("all_agents", "synthesizer")

    # 5. synthesizer -> END
    chatbot_graph.add_edge("synthesizer", END)

    # 6. Compile
    chatbot_app = chatbot_graph.compile()

The resulting graph looks like this:

    START
      |
    supervisor
      |
      +---> research ----+
      +---> budget ------+---> synthesizer ---> END
      +---> itinerary ---+
      +---> all_agents --+
      +---> synthesizer -+
